# Tumble Toy — 제품 스펙

> 2026-10-06: 현재 프로젝트는 동일한 100스테이지 캠페인의 초기 2D 탑뷰, 중기 2D 쿼터뷰, 최종 3D 구현을 보존하며 실제 게임은 최종 3D로 실행된다. 확장 기능과 완료 조건은 [캠페인 스펙](campaign-spec.md)을 우선 적용한다.

## 1. 제품 개요

**Tumble Toy**는 격자형 블록 바닥에서 표준 6면체 주사위를 굴려 목표 숫자를 맞추는 퍼즐 게임이다. 플레이어는 100개 스테이지를 진행하며 특수 타일과 아이템을 활용한다.

## 2. 핵심 목표

플레이어는 목표 타일에 도착했을 때 주사위의 윗면 숫자가 목표 타일의 요구 숫자와 같도록 해야 한다.

### 시작 화면 흐름

게임 시작 시 게임 로고와 대표 비주얼이 있는 스플래시 화면을 최소 3초간 표시한다. 초기화가 끝나면 점멸하는 터치 안내를 표시하고, 사용자가 화면을 터치하면 홈 화면으로 이동한다. 홈 화면은 현재 진행도와 이어하기, 스테이지 선택, 튜토리얼, 설정을 제공한다. 이어하기는 첫 미완료 스테이지부터 시작한다.

### 진행 잠금과 설정

- 스테이지 선택에서는 이미 클리어한 스테이지와 그 다음 도전 스테이지 1개만 활성화한다. 아직 도달하지 않은 스테이지는 잠금 상태로 표시하고 입력을 받지 않는다.
- 설정에서는 BGM 음량, 효과음 음량, 안내 음성 사용 여부를 조절한다.
- 설정값은 별도 로컬 파일에 저장해 게임 진행 기록과 분리한다.
- 스플래시와 모든 메뉴 화면은 메뉴 전용 BGM을 사용하고, 스테이지 플레이는 퍼즐 전용 BGM을 사용한다.

## 3. 지원 플랫폼과 입력

| 플랫폼 | 입력 |
| --- | --- |
| PC | 방향키 또는 WASD, Z(언두), R(재시작), Enter/Space(다음 레벨) |
| 모바일 | 하단 한 줄 컨트롤: 종료, 재시작, Undo, 방향 화살표 |

### 화면 기준

- 모바일 기준 출력 해상도는 **360×800 세로 화면**이다.
- 게임 내부 기준 캔버스도 **360×800**으로 유지한다. 게임 보드는 상단 중앙, 안내·방향 패드·언두·재시작은 하단에 배치한다.
- Godot 시뮬레이터 기본 창은 기준 캔버스의 2×인 **720×1600**으로 표시한다.
- 다른 화면 비율에서는 게임 화면을 왜곡하지 않으며, Godot의 종횡비 유지 스트레치를 사용한다.

## 4. 시각 방향

- 프로젝트에는 다음 세 개발 버전을 보존한다.
  1. **초기 버전:** 2D 탑뷰로 구현한 규칙 중심 화면.
  2. **중기 버전:** 생성 이미지 리소스를 적용한 2D 쿼터뷰.
  3. **최종 버전:** Godot 메시·카메라·조명과 실제 면 방향을 사용하는 3D 화면.
- 최종 3D의 표면은 사진풍 또는 매끈한 단색 재질이 아니라 저해상도 픽셀 아트 텍스처를 nearest 필터로 표시한다. 3D 형상과 조명은 유지하되 2D 쿼터뷰의 픽셀 밀도와 팔레트를 이어간다.
- 세 버전은 동일한 캠페인 데이터와 규칙을 공유한다. 초기·중기 버전은 내부 비교와 회귀 검증을 위해 보존한다.
- 실제 MVP는 최종 3D 버전으로 시작하며 메인 메뉴·스테이지 선택·플레이 HUD에 버전 선택 UI를 표시하지 않는다.
- 개발 검증에서는 숫자 키 1·2·3과 명령행 옵션으로 버전을 전환할 수 있다.
- 물리 엔진 기반 주사위 시뮬레이션으로 규칙 상태를 결정하지 않는다.

## 7. 리소스 제작 기록

- 클라우드 모델과 로컬 모델을 리소스 성격에 맞게 사용해 일관된 완성 품질을 확보한다.
- 각 리소스는 제작 환경(클라우드/로컬), 실제 모델명, 프롬프트, 원본 결과, 후처리, 게임 적용 위치를 기록한다.
- 지정 모델을 사용할 수 없을 때는 임의의 대체 모델로 완료 처리하지 않는다. 접근 불가 사유와 미완료 상태를 기록한다.
