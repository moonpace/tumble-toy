# Tumble Toy — 구현 계획 및 완료 조건

## 2026-10-06 메뉴·플레이 배경음악 분리

- MiniMax Music 3 BF16 로컬 MLX로 메뉴 전용 BGM-003을 새로 생성하고 프롬프트, seed, 원본, 가공과 해시를 기록한다.
- 스플래시와 모든 메뉴 페이지는 BGM-003, 스테이지는 기존 BGM-001을 재생한다.
- 같은 음악을 사용하는 메뉴 페이지 사이에서는 재생 위치를 유지하고, 메뉴와 플레이 경계를 넘을 때만 곡을 교체한다.
- 완료 조건: 두 스트림 임포트, CoreAudio 재생 위치 증가, 메뉴→플레이→메뉴 전환 검사, 전체 회귀와 최신 시뮬레이터 재실행.

구현 결과: MiniMax Music 3 BF16 로컬 MLX가 45초 요청에 반환한 11.122358초 원본으로 1.5초 순환 크로스페이드 단위를 만들고 6회 반복해 57.734150초 메뉴 루프로 가공했다. 최종 루프 경계 점프 `0.002380`은 인접 샘플 점프 99백분위 `0.041199`보다 작다. 스플래시와 모든 메뉴는 BGM-003, 스테이지는 BGM-001을 재생하며 동일 메뉴 그룹 안에서는 곡을 재시작하지 않는다. 프롬프트, seed 4103, 원본·단위·최종 해시는 `audio-generation-prompts.json`에 기록했다.

검증 결과: CoreAudio에서 메뉴 57.734초 `playing=true`·재생 위치 증가, 퍼즐 75초 전환, 메뉴 복귀를 확인했다. 규칙 100개와 100스테이지 1,537입력 재생도 통과했다. 스플래시 입력 전환까지 반영한 최신 시뮬레이터 PID 29278을 새로 실행해 OpenGL 초기화, 메뉴 BGM 재생과 프로세스 생존을 확인했다.

## 2026-10-06 런타임 오디오 재생 수정

- 증상: BGM 로그와 스트림 길이는 정상이지만 `AudioStreamWAV.load_from_file()`로 만든 플레이어가 즉시 정지해 소리가 출력되지 않았다.
- 수정: BGM, 효과음, 안내 음성과 OGG 징글을 Godot의 `res://` 리소스 로더로 불러오도록 통일한다.
- 완료 조건: CoreAudio에서 BGM `playing=true`, 재생 위치 증가, Master 버스 음소거 해제 상태 확인, 전체 회귀 검사와 최신 시뮬레이터 재실행.

구현 결과: WAV와 OGG를 Godot 리소스 로더로 통일하고 BGM 원본을 복제한 뒤 전체 샘플 범위를 루프 구간으로 지정했다. 기존 방식은 재생 상태가 즉시 `false`가 됐지만 수정 후 CoreAudio 48kHz에서 `playing=true`, Master `mute=false`, 재생 위치 증가를 확인했다. 효과음 7개와 안내 음성 6개도 같은 경로로 정상 로드된다.

## 개발 순서 — 문서 우선

문서가 코드보다 우선하는 단일 기준(Source of Truth)이다. 모든 기능은 반드시 다음 순서를 따른다.

1. **문서 업데이트:** 제품/게임플레이 스펙에 요구사항과 스펙 ID를 먼저 추가하거나 수정한다.
2. **완료 조건 정의:** 해당 스펙에 관찰 가능하고 검증 가능한 완료 조건을 작성한다.
3. **문서 검토:** 변경 범위, 의존성, 제외 범위를 문서에서 확인한다. 사용자 결정이 필요한 사항은 이 단계에서 논의한다.
4. **구현:** 확정된 스펙과 완료 조건을 만족하도록 코드·에셋을 변경한다.
5. **검증:** 완료 조건에 대응하는 자동/수동 검증 및 Godot 실행 검증을 수행한다.
6. **상태 갱신:** 구현 계획에 결과, 검증 방법, 남은 제한을 기록한다.

문서에 없는 기능은 구현하지 않는다. 문서와 기존 코드가 다르면 문서를 기준으로 코드를 수정한다.

이 순서에는 예외가 없다. 구현 또는 에셋 생성이 문서보다 먼저 발생한 경우에는 다음 기능 작업을 시작하지 않고, 즉시 해당 작업의 스펙·완료 조건·검증 결과를 문서에 보완한다.

## 기능 업데이트 실행 게이트

기능, 입력, 레벨 데이터, 화면 레이아웃 또는 에셋 참조를 변경할 때마다 다음을 수행한다.

1. `tests/rules_test.tscn`을 Godot에서 실행해 규칙 자동 테스트를 확인한다. 관련되지 않은 순수 시각 변경이라도 레벨 데이터·입력 코드에 닿았다면 실행한다.
2. 메인 씬을 Godot에서 실행해 파서·런타임 오류가 없는지 확인한다.
3. 결과와 남은 수동 검증 항목을 이 문서의 현재 추적에 갱신한다.

Godot MCP가 사용 가능한 환경에서는 MCP의 프로젝트 실행·디버그 출력으로 이 게이트를 수행한다.

시뮬레이터 실행 전에는 항상 기존 Godot 프로젝트 프로세스를 종료한다. 검증·사용자 확인을 위해 실행하는 시뮬레이터는 반드시 가장 최근 변경 사항이 반영된 새 프로세스여야 하며, 이전 실행 창을 유지하거나 재사용하지 않는다.
